# Claim to artifact map

This document exists so that a reviewer never has to take a number in the paper
on trust. Every quantitative claim the paper makes is listed here alongside the
journal it was computed from, the script that computes it, and the generated
file where the value lands. If a claim is not in this document, the paper should
not be making it, and a reviewer finding such a gap has found a real defect
worth reporting.

The reproduction contract is deliberately narrow, which is what makes it
checkable. Given the journals committed under `artifacts/`, the analysis is
deterministic: the same seed, the same permutation count, and the same input
bytes produce the same output bytes. A correct run of `scripts/reproduce_all.sh`
therefore leaves `tables/` and `figures/` unchanged, and the final stage of that
script asserts exactly this using `git status`. An empty status is the
reproduction. A non-empty status is a finding, and the diff itself names the
quantity that moved.

Collecting new journals is a separate and far more expensive activity that
contacts Azure OpenAI and provisions a confidential VM. It is documented in
`docs/REPRODUCIBILITY.md` and is not what this document covers. Everything
below re-derives the paper from evidence already gathered.

## One caveat on the reproduction contract

The contract above holds given a fixed analysis environment. The analysis is
deterministic in the strong sense that two identical invocations produce identical
bytes, but it is not stable across scikit-learn versions: the second task family's
attribute AUC moved from 0.763 to 0.733 across a version change, from identical journal
bytes and an identical seed. The nulls moved with it, the permutation rank did not
change, and no qualitative claim in this document changed. The versions the committed
values were produced under are recorded in `environment-tested.txt`, and
`docs/REPRODUCIBILITY.md` describes the episode. A reviewer reproducing slightly
different third decimals should check that file first.

## How to check one claim by hand

Every number in the manuscript is a LaTeX macro rather than a literal, which
means there is a single place to look. To check the headline attribute AUC, for
example, regenerate the macros and read the one you care about:

```
bash scripts/reproduce_all.sh
grep 'attrAUC' tables/macros.tex
```

The macro names are stable and are used verbatim in the manuscript source, so
searching the paper for `\attrAUC` and searching `tables/macros.tex` for
`attrAUC` will always agree. This is also the mechanism that makes the paper
resistant to a stale number surviving an analysis change: if a value moves, it
moves in the macro file and in the rendered PDF together, and it cannot be
updated in one place and forgotten in the other.

## The four host-observable coordinates

The claims below repeatedly distinguish four things a host can see, and the
distinction carries most of the paper's argument, so it is worth stating before
the tables. Structure is the shape of the trace, meaning which agents ran in
what order and how many round trips occurred. Timing is the per-step latency.
Egress is the size of the request the guest sends to the model provider.
Ingress is the size of the response the provider sends back.

The asymmetry that the paper turns on is that egress is composed by the guest
and can therefore be padded to a ceiling by the guest, whereas ingress is chosen
by the provider and cannot. A defence that lives inside the confidential VM has
authority over three of these coordinates and only partial authority over the
fourth.

## The wire-level measurement

This is the measurement that closes the gap between what the paper models and
what a host actually observes. The application-level numbers above are computed
from sizes the runtime records. The numbers below are computed from a packet
capture taken outside the guest, with header-only capture at 96 bytes so that no
payload is collected, and attributed to steps by partitioning the capture
timeline using the signed receipts.

| Claim | Value | Regenerated by |
|---|---|---|
| Run-level egress tracks the application's own accounting | Pearson r equal to 0.993 | `make_wire_artifacts.py` |
| Run-level ingress tracks it less closely | Pearson r equal to 0.849 | `make_wire_artifacts.py` |
| Transport inflates egress modestly | factor 1.26 | `make_wire_artifacts.py` |
| Transport inflates ingress substantially | factor 4.92 | `make_wire_artifacts.py` |
| Padded egress does not leak at the wire | AUC 0.556, null 0.565, p equal to 0.508 | `make_wire_artifacts.py` |
| Provider-chosen ingress does leak at the wire | AUC 0.742, null 0.578, p equal to 0.011 | `make_wire_artifacts.py` |
| The same asymmetry appears in application accounting | egress 0.704 at p equal to 0.015, ingress 0.787 at p at or below 0.0005 | `make_wire_artifacts.py` |

The capture covers 48 runs and 723 steps, of which 541 carried packets, yielding
2,416 attributed segments. Two details of this stage are load-bearing and both
produced a wrong answer before they were fixed, so they are worth stating
explicitly rather than leaving in the code. First, the step windows must not
overlap; an earlier version double counted packets in adjacent windows and
reported an ingress inflation factor of 6.4 rather than 4.92. Second, the
capture must be restricted to the model provider's address. The same capture
also saw an unrelated peer carrying 227 kilobytes, and including it moved the
step-level egress correlation from positive 0.45 to negative 0.04, which
inverts the conclusion. The peer is recorded in
`artifacts/wire/wire-report.json` and `reproduce_all.sh` reads it from there
rather than leaving it to the operator to remember.

The attestation evidence sits in the two `.attestation.json` files and is
verified by `traceguard verify`. One property of this evidence is worth
flagging to a reviewer because it bounds a claim the paper is careful not to
overstate: the receipts are signed and hash chained, and the confidential VM
boot is attested, but an individual receipt is not itself nonce bound or key
bound to the SEV-SNP quote. The paper therefore claims that the run happened on
an attested platform, and does not claim that a given receipt is
cryptographically inseparable from that platform's quote. The verifier refuses
to report the stronger property, and `docs/ARCHITECTURE.md` describes the two
stage binding that would be required to earn it.

The generality sweep varies three factors independently and reports each arm
separately rather than pooling, because pooling across factors would hide the

The last two rows are a single finding and should be read together. The
attribute channel is the robust one; it appears in both task families. The
membership channel appears strongly in prior authorization at 0.719 and is
absent in anti money laundering, where the point estimate of 0.604 sits below
its own null of 0.623. The paper reports this as a scope limit on the
membership result rather than as a replication, and the macro that records it is
named `familyMemberReplicates` with the value `no`.

## Claims the paper deliberately does not make

A claim map is more useful to a reviewer when it also records the boundaries, so
these are the places where an available number was judged not to support a
claim, and no claim was made.

The paper does not claim that the membership channel generalizes across task
families, for the reason given immediately above. It does not claim that the
release at epsilon and delta both zero is useful; the frontier analysis reports
that regime as vacuous with an attribute AUC of 0.50, and the accompanying
utility measurement is what quantifies its cost. It does not claim bitwise
receipt to quote binding, as described in the confidential VM section. It does
not claim that concurrency explains the fail-closed rate; that hypothesis was
tested, the six way and fifteen way figures were 19.4 and 14.1 percent with
overlapping intervals, and the hypothesis was withdrawn rather than reported.
It does not claim a structural membership leak, since structure alone yields
0.50 once length is controlled.

## The power limitation, stated plainly

The single most important limitation to understand before reading the primary
table is statistical power, and it is not hidden in an appendix because a
reviewer will find it anyway and should find it stated by the authors first.

The minimum detectable effect for the attribute analysis is 0.174. The observed
attribute signal above its calibrated null is 0.185. The margin between what the
design can detect and what it detected is therefore small. The corpus comprises
six topic groups drawn from three medical specialties, and the leave one group
out protocol means the effective number of independent units is six rather than
the number of runs. Two consequences follow. The direction and existence of the
attribute effect are supported, since the permutation p value is at or below
0.0005 against a properly calibrated within-group null. The precise magnitude is
not tightly bounded, and a reader should not treat 0.784 as a stable point
estimate of leakage in an arbitrary deployment.

Expanding the corpus to more independent specialties is the correct remedy and
is the first item in the future work discussion. It is not a defect in the
analysis so much as a bound on what this corpus can establish.

## Attacker protocol, since it affects every AUC above

Every reported AUC uses a protocol chosen to favour the attacker, so that a
negative result is meaningful. The attacker is allowed the maximum of two
attacker models, and the reported figure is the maximum of the AUC and one minus
the AUC, so that a systematically inverted classifier counts as a success rather
than a failure. Nulls are calibrated by permutation within groups, 2000
permutations at seed 20260710, which is what makes an AUC of 0.58 recognizable
as chance rather than as weak evidence. Any claim of suppression in this
document is therefore a claim that an advantaged attacker still failed, which is
the direction of error a defence paper should prefer.

The last row deserves a note. That journal predates the migration to the
confidential VM and to the current model deployments. Its numbers are carried in
the paper under an explicit `hist` prefix and are labelled as historical
wherever they appear, precisely so that no reader mistakes them for the
headline result. The two sets differ in ways the paper discusses; for instance
the historical membership figure of 0.565 against a null of 0.57 is chance,
whereas the headline membership figure of 0.721 against a null of 0.58 is not.
Reporting both, and labelling which is which, is more honest than quietly
replacing one with the other.
